# IP and Legal Flags (open)

1. **Product name.** Customer-facing name is now **"Scout OS"** (owner directive, Session 6); "Workforce OS" remains in internal identifiers. "Scout" is a common word and likely crowded in software trademarks. **A trademark clearance search for "Scout OS" (classes 9 and 42) is required before public use.** Not done. Owner decision.
2. **Bops LICENSE file not read directly.** github.com was blocked from this session; terms come from the README summary. Read the actual LICENSE before relying on the two-year Apache conversion for anything.
3. **Concept overlap.** A lead bot delegating to specialists, approval gates and per-agent inboxes are general industry patterns (also in Lindy, Relevance, CrewAI). We keep our own naming, UI and prompts. No Bops mascot-style branding, no "Boppy"-like lead-agent naming.
4. ~~**Auth library.**~~ Resolved in Milestone 1: Better Auth (MIT). See docs/design/auth-adr.md.
5. **Gmail restricted scopes.** Reading and sending mail via Gmail API needs Google's OAuth verification and, for restricted scopes, a third-party security assessment before public launch. Cost and timeline unknown. Affects Milestone 3 go-live, not development.
6. **Client data for tax/financial firms.** If the first segment includes tax preparers, client data may fall under IRS Publication 4557 / FTC Safeguards Rule expectations. Needs a review before any real client data enters the system. Development uses synthetic data only.
7. **LGPL component in the Next.js image optimizer** (libvips via sharp). Unmodified and dynamically loaded, which LGPL permits; no images are served through it today. If the product ships a desktop or on-premise build, review LGPL obligations then.
8. **Model output and customer data.** Customer emails, CRM records and invoices are sent to the model provider during planning. The provider's data-use terms (training, retention) need a review and a line in the customer terms before launch.
9. **Storm data.** NOAA Storm Prediction Center reports are US federal government works (public domain in the US). Scout stores the source and this usage statement with every upload. Live retrieval isn't built (network blocked in development); if added, check NOAA's current access terms and rate guidance first.
10. **Customer-imported prospect lists.** Scout requires an attestation of the right to use each list and stores only allow-listed columns. Purchased or scraped lists may carry license terms or be unlawful to use for marketing in some states. The attestation shifts the decision to the customer but doesn't remove our exposure; customer terms should say so. Legal review needed.
11. **Outreach compliance (CAN-SPAM, TCPA, state privacy laws).** Scout blocks email to prospects without a recorded permission and honors a do-not-contact list, enforced in code. That is a technical control, not legal compliance: sender identity and an unsubscribe link in outgoing email, privacy notices for imported personal data, and any SMS/calling (not built) need a qualified reviewer before real use. Release gate: compliance review — **not done**.
12. **Heuristic score wording.** Scores are labelled "heuristic, not a probability" and explanations avoid damage claims. Marketing copy must keep to the same claims; promising "warm leads" or "storm-damaged roofs" would contradict the product's own disclosures.
