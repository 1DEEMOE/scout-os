## Weakness register

### Correctness & trust (fixed in Wave 1)

- **C1 — Front desk is headless.** Channels, slots, approvals all exist, but there is no public booking page and no channel management UI, so the feature is unreachable by real customers. → Wave 2 (public booking page + settings UI).
- **C2 — Front desk TOCTOU races.** Slot capacity was `SELECT` then `UPDATE` — two concurrent requests could both take the last seat. Rate buckets the same, so rate limits undercounted under concurrency. → Fixed: atomic `UPDATE … WHERE reserved_count < capacity RETURNING`, atomic `INSERT … ON CONFLICT DO UPDATE … RETURNING`.
- **C3 — No member lifecycle.** You could add members (only if they already had an account) but never remove one, change a role, or invite someone new. An SMB's first employee offboarding would need SQL. → Fixed: invitations (hashed token, 7-day TTL, 25 pending cap, email-match at accept), `removeMember`, `setMemberRole` with last-owner and staff-protection rules, seats enforced at accept time.
- **C4 — Audit log not tamper-evident.** Append-only by grant, but nothing detected a doctored row written by a compromised owner connection. → Fixed: per-tenant SHA-256 hash chain (advisory-lock serialized), `verifyAuditChain` + badge on the audit page, chain columns in CSV export.
- **C5 — Approval expiry never fired.** A task could wait forever if nobody clicked. → Fixed: expiry wake-up job enqueued at request time (`ttl + 60s`); pending front-desk bookings whose approvals expire are cancelled and release the slot hold.
- **C6 — Undocumented env vars.** `DATABASE_URL_ADMIN` / `TEST_DATABASE_URL_ADMIN` were required but absent from README and `.env.example`. → Fixed, plus `WOS_INBOX_SYNC_SECONDS` and the webpack-build note for ≤4 GB machines.

### High (fixed in Wave 1)

- **H1 — PII in logs.** Customer names/emails could flow into log metadata. → Fixed: deep `scrubPii` + pino redact paths.
- **H2 — No integration disconnect.** OAuth credentials could be added but never removed. → Fixed: `disconnectIntegration` (managers, tier 4 audit, deletes dependent mailboxes which stops the background sync chain).
- **H3 — Unmetered task creation.** → Fixed: 30 tasks/hour/user, `RATE_LIMITED` error.
- **H4 — No background inbox sync.** Mail only moved when a user clicked "sync". → Fixed: self-perpetuating pg-boss chain per mailbox (`inbox.sync` queue, singleton per mailbox, stops when the mailbox is disconnected).
- **H5 — No observability hook.** → Fixed: optional OTel SDK (no-op without `OTEL_EXPORTER_OTLP_ENDPOINT`; kept out of the Next build graph via dynamic import).
- **H6 — Booking holds leaked; job photos fully mutable by app.** → Fixed in 0018 + lazy expiry + column-restricted UPDATE grant.

### Market gaps (the "why nobody else has this" list)

- **M1 — Speed-to-lead is the whole game and nobody SMB-priced owns it.** 78% of customers hire the first responder; ~88% of contractors take >5 min (many never respond); SMBs miss 27–62% of calls (~$126k/yr). Missed-call-text-back tools do one channel; AI SDRs (11x, Artisan at $45–65k/yr, $999+/mo) are outbound-only and enterprise-priced. → Wave 2: speed-to-lead autopilot.
- **M2 — SMBs run ~8 disconnected tools (~$187/rep/mo) because each tool sees one silo.** Nobody lets you ask "who hasn't paid, who booked this week, which leads went cold" in one sentence and act on the answer. → Wave 2: chat-as-OS cross-domain tools.
- **M3 — Trust is the SMB's real product and no platform productizes it.** Job photo chains + approval-audited history already exist internally; there is no shareable proof page. → Wave 3.
- **M4 — AI-to-AI booking** (a customer's AI agent booking with the business's front desk) — front desk protocol already handles `requesterKind: ai_agent` with disclosure; first-mover surface is the public page (C1).
- **M5 — Answer-engine visibility** (`ai_answer_checks`) exists but is mocked and unexposed; real providers need owner sign-off (cost).
- **M6 — Reactivation money left in the CRM.** Nurture sequences over the consented customer list are a routine away. → Wave 3.
